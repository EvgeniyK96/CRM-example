# CRM кондитерской фабрики — сценарий и план

Учебный проект (не для продакшена). Стек: Django 5 + DRF + djoser/JWT (бэкенд, на базе шаблона), React SPA + Vite + TypeScript (фронтенд), SQLite → PostgreSQL.

## 1. Роли

| Роль (код) | Доступ |
|---|---|
| `admin` | Всё, пользователи и роли, справочники |
| `sales` — менеджер по продажам | Клиенты, заказы, отгрузки (просмотр) |
| `hr` — отдел кадров | Сотрудники, должности, цеха, табель, отпуска и больничные |
| `accountant` — бухгалтерия | План счетов, проводки, счета и оплаты, расчёт зарплаты, отчёты |
| `technologist` — технолог | Номенклатура, рецептуры (версии) |
| `shop_head` — начальник цеха | Производственные задания своего цеха, запуск и завершение, брак |
| `storekeeper` — кладовщик | Приход сырья, остатки, закупки, отгрузка |

## 2. Предметная область

Цеха: торты и пирожные, пряничный, вафельный, сдобный.
Клиенты: оптовые покупатели, магазины, фирменные магазины.
Заказ клиента → система проверяет остатки готовой продукции → дефицит превращается в производственные задания по цехам → запуск списывает сырьё по рецептуре (FEFO) → выпуск создаёт партию готовой продукции со сроком годности → отгрузка (FEFO) → счёт и оплата.

### Статусы
- Заказ: `new` → `confirmed` → `in_production` → `ready` → `shipped` (+ `cancelled`).
- Задание: `planned` → `in_progress` → `done` (+ `cancelled`).
- Оплата: `unpaid` / `partial` / `paid`.

### Сквозной сценарий
1. Менеджер создаёт заказ магазина (200 пряников, 50 тортов), подтверждает.
2. Система создаёт задания в пряничный и тортовый цеха на недостающее количество.
3. Начальник цеха запускает задание. Сырьё списывается по рецептуре по FEFO. Если не хватает, запуск блокируется и создаётся заявка на закупку.
4. Завершение: фактический выход и брак → партия готовой продукции, привязанная к партиям сырья (прослеживаемость).
5. Все задания выполнены → заказ `ready`. Кладовщик оформляет отгрузку.
6. Бухгалтерия: счёт, оплата, автоматические проводки; себестоимость партии.
7. Конец месяца: табель → расчёт зарплаты → проводки → ведомость.

## 3. Модули и сущности

### accounts
Кастомный `User` (роль), JWT через djoser, права по ролям.

### hr — отдел кадров
Цеха/подразделения, должности, сотрудники (ФИО, дата рождения, ИИН/ИНН, контакты, дата приёма/увольнения, статус), кадровые приказы (приём, перевод, увольнение), трудовые договоры (оклад или сдельная ставка), табель (дни/часы), отпуска, больничные, командировки.

### accounting — бухгалтерия
- План счетов, журнал проводок (двойная запись), контрагенты (из клиентов и поставщиков).
- Автопроводки из бизнес-событий: приход сырья, списание в производство, выпуск продукции, отгрузка (выручка и себестоимость), оплата.
- Зарплата: начисления (оклад, сдельная, премии, отпускные, больничные), удержания (налоги и взносы со **ставками в настройках**, т.к. учебная упрощённая модель), расчётный листок, ведомость, выплата.
- Отчёты: оборотно-сальдовая ведомость, карточка счёта, расчётная ведомость, дебиторка.

### catalog
Единицы измерения, категории, номенклатура (сырьё, готовая продукция), поставщики.

### recipes
Рецептуры с версиями (выход партии, строки сырья, потери).

### warehouse
Партии (сырьё и продукция) со сроками годности, складские движения (приход, расход, выпуск, отгрузка, брак), остаток = сумма движений, FEFO.

### purchasing
Заявка поставщику, приёмка → партии сырья.

### sales
Клиенты (тип, адреса, условия оплаты), заказы и строки, отгрузки.

### production
Производственные задания, запуск (списание), завершение (выпуск), брак, прослеживаемость.

### reports
Дашборд: загрузка цехов, остатки ниже минимума, истекающие сроки, выручка, брак, прослеживаемость партии.

## 5. Этапы (~8–10 недель)

| # | Этап | Результат |
|---|---|---|
| 0 | Каркас: venv, зависимости, CORS, настройки, каркас frontend, CI | Сервер и фронт стартуют |
| 1 | `accounts` + `hr` (база): роли, права, цеха, должности, сотрудники | Вход по ролям, учёт сотрудников |
| 2 | `catalog` + `recipes` | Справочники и рецептуры (технолог) |
| 3 | `warehouse` + `purchasing` | Партии, движения, FEFO, приход |
| 4 | `sales`: клиенты, заказы | Заказы со статусами |
| 5 | `production` | Задания, запуск/выпуск, брак, прослеживаемость |
| 6 | Отгрузка | Заказ → отгружен |
| 7 | `accounting` I: план счетов, проводки, счета, оплаты, автопроводки | Финансовый цикл |
| 8 | `hr` II + `accounting` II: табель, отпуска, больничные, зарплата, ведомости | Зарплата |
| 9 | `reports`: дашборд, экспорт CSV | Аналитика |
| 10 | Демо-данные, тесты, документация, ER-диаграмма | Готовый проект |

Фронтенд делается вместе с каждым этапом: API → экран.

### Статус
- [x] Этап 0 — каркас
- [x] Этап 1 — роли, пользователи, сотрудники
- [x] Этап 2 — каталог (единицы, категории, номенклатура, поставщики), рецептуры с версиями и калькулятором
- [ ] Этап 3 — склад и закупки

### Демо-данные
`python manage.py seed_recipes` — цеха и должности, каталог (25 видов сырья, 9 продуктов, 5 поставщиков) и активные рецептуры. Команды идемпотентны.

## 6. Допущения
- Налоги и взносы зарплаты упрощены и задаются в настройках (не юридически точный расчёт).
- SQLite для разработки, PostgreSQL через `DATABASE_URL`.
- Складские остатки считаются из движений; операции атомарны (`transaction.atomic`, `select_for_update`).
