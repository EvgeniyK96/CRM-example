# Сценарий демонстрации

Сквозной путь через все модули: **заказ клиента → производство → отгрузка → деньги → зарплата**.
Рассчитан на чистую базу после `python manage.py seed_demo` (пароль всех пользователей — `demo12345`).
На каждом шаге указано, кто его выполняет и что должно получиться.

Время прохода — 20–30 минут. Шаги 1–6 — основная цепочка; 7–9 можно показывать отдельно.

---

## 0. Что уже есть после `seed_demo`

- 25 видов сырья на складе (две поставки; у молочных продуктов из старой поставки **истёк срок**), заявка
  поставщику на муку в статусе «Отправлена».
- 9 продуктов с активными рецептурами, начальные остатки части продукции.
- 7 клиентов и 4 заказа: один уже отгружен, два в производстве, один готов к отгрузке.
- Задания: выполненное, в работе и запланированные.
- Бухгалтерия: проводки по всем операциям, счёт и частичная оплата, оплата поставщику, аванс фирменного магазина.
- Кадры: приказы, отпуск и больничный в прошлом месяце; зарплата за прошлый месяц выплачена, за текущий — черновик.

## 1. Заказ клиента — `sales`

1. «Заказы клиентов» → «Создать»: клиент **Кофейня «Корица»**, дата отгрузки — послезавтра.
2. В карточке добавить строки: **Пряник имбирный глазированный — 30 шт**, **Торт «Медовик» 1 кг — 4 шт**.
   Цену не указывать → «Сохранить».

**Ожидается:** цены подставились из прайса со скидкой клиента 5% (имбирный пряник 350 → 332,50).
Блок «Наличие на …» показывает: пряник есть на складе, медовик нужно произвести.

3. «Подтвердить».

**Ожидается:** статус «Подтверждён»; пряник зарезервирован, медовик — «Произвести 4 шт».
Тот же пряник для других заказов теперь доступен за вычетом резерва.

## 2. Планирование — `shop_head`

1. «Задания» — вверху блок «Потребность из заказов, ещё не поставленная в задания» с медовиком.
2. «Сформировать задания».

**Ожидается:** создано задание в цехе тортов на дату накануне отгрузки; заказ перешёл в «В производстве».

## 3. Производство — `shop_cakes` (начальник цеха тортов)

1. «Задания» — по умолчанию показан только свой цех. Открыть задание на медовик.
2. Блок «Сырьё на …»: нужно / доступно / не хватает. Яйца считаются целыми штуками.
3. «Запустить» → подтвердить.

**Ожидается:** сырьё списано по FEFO — в блоке «Списанное сырьё» партии с ближайшим сроком годности;
в «Остатках» сырья стало меньше.

4. «Завершить»: выпущено 4, брак 0.

**Ожидается:** создана партия продукции с себестоимостью «стоимость сырья / выпуск»; заказ «Корицы»
стал «Готов к отгрузке». Попробуйте открыть задание пряничного цеха — у `shop_cakes` там только просмотр.

## 4. Отгрузка — `storekeeper`

1. «Отгрузки» — заказ «Корицы» в очереди «Готовы к отгрузке» → «Отгрузить», указать водителя.
2. Открылась накладная: партии, выручка, себестоимость, валовая прибыль. «Печатная форма».

**Ожидается:** в печатной форме у каждого продукта перечислены партии и сроки годности; заказ «Отгружен».

## 5. Прослеживаемость — любая роль

Из накладной кликнуть номер партии медовика → «Сделана из партий сырья» → кликнуть партию яиц.

**Ожидается:** цепочка в обе стороны: продукция ← партии сырья ← поставщики, и партия сырья → в какие
партии продукции ушла → каким клиентам отгружена.

## 6. Деньги — `accountant`

1. «Счета покупателям» — счёт на отгрузку «Корицы» создан автоматически, срок оплаты = дата + отсрочка 7 дней.
2. «Оплата» в строке счёта → провести частичную оплату.

**Ожидается:** долг клиента уменьшился, статус счёта «Оплачен частично».

3. «Журнал операций» — автопроводки по всей цепочке: запуск (Дт 8110 — Кт 1310), выпуск (Дт 1320 — Кт 8110),
   отгрузка (Дт 1210 — Кт 6010, Дт 7010 — Кт 1320), платёж (Дт 1030 — Кт 1210). Клик по операции ведёт в документ.
4. «Финансовые отчёты» → «Оборотно-сальдовая ведомость» — итоги по дебету и кредиту совпадают на всех уровнях;
   клик по счёту открывает его карточку. «Прибыли и убытки» — выручка, себестоимость, валовая прибыль.

---

## 7. Склад и закупки — `storekeeper`

1. «Остатки» → раскрыть «Сливки 33%» — просроченная партия. «Списать» (форма заполнится сама).
2. «Заявки поставщикам» → отправленная заявка на муку → «Принять поставку» → уменьшить количество → «Сохранить» →
   «Провести».

**Ожидается:** партии на складе со сроком годности по нормативу; заявка «Получена частично»;
в бухгалтерии — проводки списания (Дт 7470) и приёмки (Дт 1310 — Кт 3310).

## 8. Рецептуры — `tech`

«Рецептуры» → любая активная → «Новая версия на основе этой» → изменить количество сырья → «Сохранить» → «Активировать».

**Ожидается:** прежняя версия ушла в архив; калькулятор показывает новую потребность; уже созданные задания
продолжают использовать ту версию, по которой были спланированы.

## 9. Кадры и зарплата — `hr`, затем `accountant`

1. `hr`: «Отсутствия» → отпуск сотруднику цеха в текущем месяце; «Кадровые приказы» → изменение оклада.
2. `hr`: «Табель» — у сотрудника появились дни «О».
3. `accountant`: «Зарплата» → ведомость текущего месяца → «Пересчитать по табелю», ввести премию в таблице →
   «Провести» → «Выплатить».

**Ожидается:** отпускные и новый оклад в расчётном листке; проводки начисления (Дт 7110/7210 — Кт 3350),
удержаний (Кт 3120/3213/3220) и выплаты; на главной у сотрудника с учётной записью — «Мой расчётный листок».

## Что ещё показать

- **Дашборд по ролям** — главная страница у `storekeeper`, `sales`, `accountant` выглядит по-разному;
  у каждого графика есть табличный вид.
- **«Аналитика»** — продажи, производство, запасы с выгрузкой в CSV (открывается в Excel).
- **Защита данных** — кладовщик не видит выручку, менеджер не может отгрузить, начальник цеха не запустит
  задание чужого цеха, у уволенного сотрудника блокируется вход.
- **Swagger** — `http://127.0.0.1:8000/swagger/`, авторизация кнопкой «Authorize» с JWT.
